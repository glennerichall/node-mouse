# ARCH — ARCH-036 — 2026-10-07

État: terminé

## Objectif et critères d'acceptation

Regrouper les subscribers de transport dans une arborescence dédiée à la
connexion, sur le modèle des routeurs REST, sans déplacer les actions métier.

- les subscribers d'entrée, de remotes et de connexion résident sous
  `server/connection/subscribers/`;
- le service de souscriptions et les tests utilisent les nouveaux chemins;
- le contrat de canal et le routage vers les services métier restent inchangés;
- la suite complète et le contrôle de version passent.

## Décisions et raisons

Les subscribers sont des composants de liaison entre un canal de transport et
les services métier. Ils sont donc regroupés avec les composants de connexion,
tandis que les actions exécutées restent dans `server/remotes/`. Cette
séparation prépare l'ajout d'autres adapters de transport sans disperser les
points d'entrée événementiels.

## Modifications apportées

- déplacé et renommé les neuf subscribers dans

- documenté ARCH-036 dans l'axe Architecture, la roadmap globale et l'index
