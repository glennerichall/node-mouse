# Architecture — ARCH-019 — 2026-10-07
État: terminé

## Objectif et critères d'acceptation

Faire respecter par le programme la frontière entre configuration système et
configuration persistée : Joi valide la première au démarrage et garde les
écritures de la seconde dans l'API administrateur.

## Décisions et raisons

La validation manuelle existante ne couvrait pas les bornes numériques et
laissait le payload HTTP accepter des champs inattendus. Joi est introduit à la
frontière, avec un schéma strict pour la configuration système et un schéma
construit à partir du catalogue fonctionnel pour chaque valeur persistée.

## Modifications apportées

- Ajout de `systemConfigSchema.js`, schéma Joi strict et validation agrégée au
  chargement de `getStartupSystemConfigSnapshot()`.
- Ajout de `getConfigValueSchema()` pour générer les guards Joi des champs
  fonctionnels.
- Le routeur administrateur valide maintenant le payload et la valeur avant
  toute écriture ou réinitialisation.
- Ajout de tests pour les bornes API et le rejet d'une valeur système invalide.
- Ajout de la dépendance `joi` et version patch portée à `6.19.18`.

## Vérifications et résultats

- Tests ciblés : 2 suites, 15 tests réussis.
- `npm test -- --runInBand` : 101 suites, 346 tests réussis.
- `npm run check:version` : réussi.
- `git diff --check` : réussi.

## Blocages / risques / suite

Aucun blocage. Les erreurs HTTP restent volontairement génériques; les détails
Joi ne sont pas renvoyés au client.
