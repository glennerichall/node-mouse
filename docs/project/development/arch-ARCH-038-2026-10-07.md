# ARCH — ARCH-038 — 2026-10-07

État: terminé

## Objectif et critères d'acceptation

Rapprocher le guard administrateur de son subscriber et uniformiser les
réponses d'action pour les transports.

- le guard est monté sur les événements `admin:*` uniquement;
- les réponses admin et QR partagent la même abstraction;
- le contexte de sécurité transite dans le channel;
- les tests et la version passent.

## Décisions et raisons

Le guard admin est une règle du flux d'événements administrateur, pas une règle
globale du transport Socket.IO. Il est donc composé dans le subscriber admin,
où chaque événement connaît son action. `sendActionResponse` normalise ensuite
le payload sans imposer Socket.IO, WebRTC ou HTTP au subscriber.

## Modifications apportées

- déplacé et adapté le guard vers `server/connection/subscribers/admin.guard.js`;
- monté ce guard avant chaque handler `admin:*`;
- retiré son enregistrement global de `createSocketGuards`;
- ajouté `sendActionResponse` et migré les subscribers admin et QR;
- exposé `securityContext` sur le channel Socket.IO adapté;
- adapté les tests de garde, de souscription et de bootstrap;
- supprimé l'ancien responder Socket.IO devenu sans consommateur et déplacé
  son test vers `send-action-response.test.js`;
- incrémenté la version patch de `6.19.37` à `6.19.38`.
