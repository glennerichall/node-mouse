# ARCH — ARCH-039 — 2026-10-07

État: terminé

## Objectif et critères d'acceptation

Aligner les subscribers sur le contrat fluent de l'adapter de canal et rendre
la réponse directement disponible dans le callback.

- payload absent normalisé par l'adapter;
- appels `channel.on` chaînables;
- réponses directes via `response`;
- suppression des valeurs par défaut dans les callbacks;
- tests et version valides.

## Décisions et raisons

Le transport est responsable de normaliser son entrée. Les subscribers ne
doivent donc pas répéter `payload = {}`. De même, `response` est déjà
l'abstraction de réponse du canal; un helper supplémentaire recréait un
couplage et masquait le nouveau contrat.

## Modifications apportées

- l'adapter Socket.IO normalise `undefined` en `{}` avant le chaînage;
- `admin.subscriber.js` utilise une chaîne directe de `.on(...)`;
- les callbacks admin et QR appellent directement `response?.({...})`;
- supprimé `sendActionResponse` et ses tests dédiés;
- retiré les valeurs par défaut `payload = {}` des subscribers browser, input
  et VLC;
- incrémenté la version patch de `6.19.38` à `6.19.39`.

## Vérifications et résultats

- tests ciblés: 4 suites, 8 tests passés;
- suite complète: 110 suites, 373 tests passés;
- `npm run check:version`: réussi;
- `git diff --check`: réussi.

## Blocages / risques / suite

Aucun blocage. Les futurs adapters devront fournir la même garantie de payload
et un callback `response` compatible avec le contrat de channel.
