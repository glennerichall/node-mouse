# Architecture — ARCH-034 — 2026-10-07
État: terminé

## Objectif et critères d'acceptation

Introduire l'adapter transport qui permet aux subscribers d'utiliser un canal
avec une API proche d'Express, notamment pour l'ajout futur de guards.

## Décisions et raisons

Le socket Socket.IO n'est plus transmis directement au service de souscriptions.
L'adapter expose `on(event, ...callbacks)` et `emit`, traduit les arguments
Socket.IO en `(payload, response, next)` et enchaîne les callbacks uniquement
quand `next()` est appelé.

## Modifications apportées

- Ajout de `createSocketChannelAdapter`.
- Adaptation du bootstrap Socket.IO avant l'appel aux subscribers.
- Mise à jour du contrat `ClientChannel` et ajout de tests de chaîne,
  acknowledgement, erreurs et retour fluent.
- Version patch portée à `6.19.34`.

## Vérifications et résultats

- Tests ciblés : 3 suites, 7 tests réussis.
- `npm test -- --runInBand` : 110 suites, 374 tests réussis.
- `npm run check:version` : réussi.
- `git diff --check` : réussi.

## Blocages / risques / suite

Aucun blocage. Les guards peuvent maintenant être ajoutés au niveau du canal
sans introduire de dispatcher global ni modifier les subscribers métier.
