# ARCH — ARCH-037 — 2026-10-07

État: terminé

## Objectif et critères d'acceptation

Faire porter la réponse des actions administrateur par le paramètre `response`
du contrat de callback de canal, au lieu de coupler le subscriber à un
responder Socket.IO.

- le subscriber utilise `response`;
- le payload de réponse reste compatible;
- l'absence de callback est tolérée;
- les tests et la version passent.

## Décisions et raisons

Le subscriber doit rester indépendant du transport. L'adapter de canal fournit
la réponse adaptée au transport; le subscriber ne doit donc plus appeler
`createSocketActionResponder` ni émettre directement un événement Socket.IO.

## Modifications apportées

- supprimé l'import de `createSocketActionResponder` dans
  `admin.subscriber.js`;
- utilisé le second argument des callbacks pour répondre aux actions;
- conservé le format `{action, ok, message, openUrl}`;
- adapté le test du subscriber pour vérifier l'acknowledgement;
- ajouté ARCH-037 aux documents de roadmap;
- incrémenté la version patch de `6.19.36` à `6.19.37`.

## Vérifications et résultats

- tests ciblés: 2 suites, 3 tests passés;
- suite complète: 111 suites, 377 tests passés;
- `npm run check:version`: réussi;
- `git diff --check`: réussi.

## Blocages / risques / suite

Aucun blocage. `socket-action-responder.js` reste disponible pour les autres
consommateurs éventuels, mais le subscriber admin n'en dépend plus.
