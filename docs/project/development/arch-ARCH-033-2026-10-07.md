# Architecture — ARCH-033 — 2026-10-07
État: terminé

## Objectif et critères d'acceptation

Supprimer l'alias historique `legacyQrActions` afin que le subscriber admin
utilise le même contrat explicite que le subscriber QR.

## Décisions et raisons

Les actions QR n'ont pas deux implémentations ni deux contrats : elles sont
partagées par les subscribers admin et QR. Le nom `qrActions` exprime donc la
responsabilité réelle et évite de préserver une compatibilité fictive.

## Modifications apportées

- Renommage de `legacyQrActions` en `qrActions` dans le subscriber admin,
  l'injection du service et les tests.
- Vérification qu'aucune référence `legacyQrActions` ne subsiste.
- Version patch portée à `6.19.33`.

## Vérifications et résultats

- Tests ciblés : subscriber admin et souscriptions transport réussis.
- `npm test -- --runInBand` : 109 suites, 371 tests réussis.
- `npm run check:version` : réussi.
- `git diff --check` : réussi.

## Blocages / risques / suite

Aucun blocage. La validation locale des payloads peut maintenant être ajoutée
subscriber par subscriber sans alias historique à préserver.
