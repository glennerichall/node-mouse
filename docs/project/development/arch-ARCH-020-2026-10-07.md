# Architecture — ARCH-020 — 2026-10-07
État: terminé

## Objectif et critères d'acceptation

Extraire la validation des écritures de configuration hors du routeur afin de
fournir un middleware autonome, monté explicitement et testable sans Express
complet ni persistance.

## Décisions et raisons

Le routeur doit composer la ressource HTTP, pas implémenter les règles Joi. Le
middleware `validateConfigPatch` possède donc le contrat de rejet HTTP et place
la valeur convertie dans `req.configPatch`; le handler ne persiste qu'une
valeur déjà validée.

## Modifications apportées

- Ajout de `config-validation.middleware.js` avec validation du chemin,
  payload, type, bornes, options et reset `null`.
- Montage du guard sur `PATCH /admin/configs/:configId`.
- Suppression de la validation Joi et de la conversion depuis le routeur.
- Ajout de tests unitaires directs du middleware.
- Version patch portée à `6.19.19`.

## Vérifications et résultats

- Tests ciblés : 2 suites, 10 tests réussis.
- `npm test -- --runInBand` : 102 suites, 350 tests réussis.
- `npm run check:version` : réussi.
- `git diff --check` : réussi.

## Blocages / risques / suite

Aucun blocage. Le même motif de middleware pourra être appliqué aux futurs
endpoints d'écriture sans déplacer la logique métier dans les routeurs.
