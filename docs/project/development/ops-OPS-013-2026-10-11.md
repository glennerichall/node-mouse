# Exploitation — OPS-013 — 2026-10-11

## Objectif

Empêcher le chargement de `better-sqlite3` 13 sous Node.js 22.12, où son
extension Node-API 10 segfaultait, et donner un diagnostic exploitable.

## Modifications

- Fixer Node.js 22.14.0 comme version minimale dans `engines`, le setup CLI,
  le setup de développement et la documentation d'installation.
- Vérifier le runtime avant l'import du serveur et avant le chargement dynamique
  de l'addon SQLite, afin qu'un runtime incompatible ne puisse pas déclencher
  le crash natif pendant la résolution des modules.
- Ajouter un test unitaire de frontière (22.13 rejeté, 22.14 accepté) et
  ajuster les tests du setup au nouveau minimum.

## Vérification

- `npm test -- --runTestsByPath test/unit/supported-node-runtime.test.js test/unit/setup-command.test.js test/unit/dev-setup-linux.test.js --coverage=false` : 3 suites, 25 tests réussis.
- Sous Node.js 22.12.0, `node index.js` termine avec le message de prérequis et
  le code 1, sans segfault.
- `git diff --check` et `bash -n dev/setup-linux.sh` : réussis.
- L'import direct du fournisseur SQLite sous Node.js 22.12.0 lève aussi
  l'erreur de prérequis avant l'import natif.

## Version

Aucun bump : aucune préparation de publication n'a été demandée.
