# Sécurité — SEC-009 — 2026-10-02

État: terminé.

## Objectif et critères d'acceptation

- Une session `controller` créée par le QR charge la configuration cliente et
  ouvre son flux de mises à jour sans réponse 403.
- Les lectures nécessaires à la télécommande utilisent `/api/client/*`; les
  mutations et données d'administration restent sous `/api/admin/*`.
- Le flux client n'expose que les clés fonctionnelles nécessaires et jamais la
  configuration système complète, l'adresse ou le MAC du téléviseur.
- Le garde administrateur continue de refuser les contrôleurs sur
  `/api/admin/*`.
- Un test anti-régression couvre les URL utilisées par le client et le filtrage
  des événements de configuration.

## Décisions et raisons

- Le 403 est légitime sur `/api/admin/subs/configs`; c'est le client qui appelle
  une ressource du mauvais domaine d'autorisation.
- Les routes clientes sont authentifiées par le garde de session commun, mais
  ne passent pas par `guardAdmin`.
- Les handlers de lecture des remotes existants sont réutilisés afin d'éviter
  une divergence entre vues admin et client.

## Modifications apportées

- Ajouté les ressources authentifiées en lecture seule `/api/client/config`,
  `/api/client/remotes`, `/api/client/remotes/browsers` et
  `/api/client/subs/*`.
- Migré le backend du navigateur vers ces ressources; la page d'administration
  conserve ses routes `/api/admin/*` et son garde `admin`.
- Défini une liste explicite de clés de configuration clientes et un canal SSE
  séparé qui ne transporte que les clés autorisées modifiées.
- Désactivé les actions administrateur dans l'état client lorsque la session a
  le rôle `controller`.
- Réutilisé le même routeur de catalogue des remotes pour les lectures admin et
  client afin d'éviter une seconde implémentation.

## Vérifications et résultats

- Le test anti-régression des URL échoue avant correction avec cinq appels à
  `/api/admin/*`, puis réussit avec `/api/client/*`.
- Tests ciblés: 7 réussis sur 7, incluant filtrage des secrets et maintien du
  refus admin pour un contrôleur.
- Suite unitaire complète: 256 tests réussis sur 256, 72 suites sur 72.
- Tests navigateur Playwright: 22 réussis sur 22.
- `npm run check:version` et `git diff --check`: réussis.

## Blocages / risques / suite

- Aucun blocage identifié. La vérification finale sur le téléphone ayant scanné
  le QR reste recommandée après redémarrage du serveur.
